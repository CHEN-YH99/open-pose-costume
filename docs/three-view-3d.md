# 三视图与 3D 建模

## 使用流程

1. 在生成页面选择人物和服饰，勾选“生成三视图”。服饰仍为必选；姿势参考变为可选，三视图统一采用直立、手臂略离身体的参考姿势。
2. 比例仅保留 `16:9 (1536×864)` 和 `3:2 (1536×1024)`，默认 `16:9`。取消勾选恢复普通模式的比例；不会把三视图模式写入全局生图配置。
3. 生成一张正面、人物自身左侧、背面横向排列的超写实三视图拼图。三视图固定为摄影级真实感，保留人物身份与服饰设计，但不继承动漫或插画画风；统一柔和漫射棚光，全身清晰，呈现自然皮肤、发丝、织物与鞋履材质。补充、自定义提示词及旧三视图任务重试在提交时均附加固定超写实约束；普通单图模式保留原风格选择。图片生成仍使用当前配置的图片服务，默认 Atomflow `gpt-image-2`。提示词约束不保证实际生成效果，仍需人工验收写实程度、三视角一致性和完整入画。
4. 检查下方三个裁切预览，按百分比调整左边距、上边距、宽度和高度。初始裁切是等宽三分之一，并非图像识别；不保证生成图严格遵循排版。每个裁切区必须在图片范围内、互不重叠；最长边缩放到最多 2048 像素后，两边仍需不少于 256 像素。保留头部、衣摆、鞋履和边距。
5. 如果实际侧面是人物自身右侧，可切换“侧面方向”。确认三个视角对应同一人物、服饰和姿势后，勾选确认项，单独点击“生成 3D”。此时才调用后端配置的混元或 Tripo 建模并消耗其账户额度。
6. 模型完成后在固定 `1:1` 外框内查看；拖拽旋转、滚轮或双指缩放、自动旋转、复位视角，也可下载 GLB。图片预览仍等比完整显示，不改变原图尺寸。

已有三视图结果时，可使用“导入 GLB 预览”验证查看器，不调用建模 API。只接受资源内嵌的 GLB 2.0，最大 50 MB；外链贴图、外链缓冲区、不合法头部和缺失网格的文件会被拒绝。该检查为基本结构校验，不等同于完整的 glTF 规范验证。

## 本地建模后端

前端不持有混元或 Tripo API Key。使用已有的 `server/index.mjs` 托管建模任务；所有 `/api/model-jobs` 请求由独立的 `server/model-jobs.mjs` 处理，不改变原有 `/api/jobs` 图片任务接口。服务商在后端选择，页面无需更换配置方式。

启动前检查 `8788` 端口。若旧后端仍在运行，先在**启动它的终端**按 `Ctrl+C`停止旧进程，再用新配置启动；不要重复启动或误停其他服务。以下设置仅作用于当前终端及其子进程，不需要修改 `.env`，也不要把真实密钥提交到仓库。

### 混元 OpenAI 兼容 API Key

适用于在腾讯云**混元生3D的 OpenAI 兼容 API KEY 页面**创建的 Key，不是原生云 API 的 SecretId/SecretKey，也不是通用聊天模型的 Key。

```powershell
$env:MODEL_PROVIDER = 'hunyuan'
$env:HUNYUAN_API_KEY = '<你刚创建的混元生3D OpenAI 兼容 API Key>'
$env:MODEL_ACCESS_TOKEN = '<自行生成的至少 32 字符随机后端访问令牌>'
npm run server:start
```

默认使用混元专业版 `3.0`，也可在启动前设置 `$env:HUNYUAN_MODEL = '3.1'`。官方兼容接口是 `https://api.ai3d.cloud.tencent.com`，下游提交和查询分别使用 `POST /v1/ai3d/submit`、`POST /v1/ai3d/query`；它不是聊天接口，也不应直接填入页面后端地址。

请先在腾讯云确认已开通服务并有可用积分。创建 API Key 不等于已领取免费额度。按当前官方计费，Normal 基础生成 20 积分，多视图附加 10 积分，三视图通常合计 30 积分；最终以控制台计费为准。本适配不额外指定 PBR、面数或转换格式，避免相应附加费用。不设置 `ResultFormat` 时官方默认返回 GLB 和 OBJ，不要把不合法的 `ResultFormat: "GLB"` 当作必需参数。

### Tripo（兼容原有配置）

```powershell
$env:MODEL_PROVIDER = 'tripo'
$env:TRIPO_API_KEY = '<你的 Tripo API Key>'
$env:MODEL_ACCESS_TOKEN = '<自行生成的至少 32 字符随机后端访问令牌>'
npm run server:start
```

不设置 `MODEL_PROVIDER` 时仍默认 Tripo；配置错误不会自动切换到另一家服务商。

### 页面填写

在结果面板“建模服务配置”中填写：

- 后端 API 地址：`http://127.0.0.1:8788/api`
- 后端访问令牌：与 `MODEL_ACCESS_TOKEN` **完全一致**，不是混元或 Tripo API Key。

令牌仅存于当前标签页的 `sessionStorage`，服务地址存于 `localStorage`。它们不会写入生成历史或分享链接。访问令牌不足 32 字符、对应服务商密钥缺失、供应商名称／API 根地址／模型配置不合法时，后端返回 `service_unavailable`，不会发送付费请求。`/api` 根路径并非服务状态接口，直接打开出现 `not_found` 不代表建模接口故障；`/api/healthz` 仅用于检查 Node 后端存活，不代表建模配置或上游额度有效。

## 任务、错误与资源边界

- Tripo v3：依次 `POST /files` 上传三张 PNG，再通过带 `front`、`left/right`、`back` 槽位的 `POST /generation/multiview-to-model` 建模，使用 `GET /tasks/{task_id}` 查询。固定开启贴图与 PBR，标准贴图质量，网格上限 30,000 面。不发起自动重建、自动升级或其他付费后处理。
- 混元兼容接口：正面使用 `ImageUrl.Url` 的 PNG data URL；侧面和背面按官方专业版的 `MultiViewImages`／`ViewType`／`ViewImageBase64` 结构传入，侧面保持人物自身 `left` 或 `right`。查询只接受 `WAIT/RUN/FAIL/DONE`，只下载 `ResultFile3Ds` 中 `Type: "GLB"` 的结果，保留签名 URL 的查询参数。界面百分比仅表示本地阶段，不是腾讯提供的实际生成进度。
- 混元三图归一化后的 base64 编码合计（包括主图 data URL 前缀）不得超过 8 MiB；超过会在任何上游请求前返回 `request_too_large`。请缩小三张图后再提交，不自动降低画质或改用单图。
- 上传仅接受三张 PNG/JPEG；每张最多 5 MB，解码上限 1600 万像素，归一化后最长边不超过 2048。原始三视图读取上限 20 MB／4000 万像素。
- 建模任务串行执行，最多 4 个在途任务。记录上限 8 个，GLB 缓存上限 128 MB，终态记录保留最多 30 分钟；空间紧张时最旧终态记录会提前淘汰。缓存与队列均在内存中，服务重启不保留任务。
- 后端任务等待最多 12 分钟，前端最多 15 分钟。网络恢复重试使用原任务凭证；若提交响应丢失，使用同一幂等标识恢复，不重复创建付费任务。幂等保护仅在该后端进程与记录保留期限内有效。
- 上游查询的暂时故障仅重试查询，不重新提交建模。付费提交结果不确定或等待超时，必须先检查当前服务商账户记录，避免重复扣费。再次确认并生成会创建新任务。
- “停止等待”、切换到其他图片或离开生成页面会停止客户端等待并尝试标记后端任务取消；官方文档未提供任务取消接口，不能保证终止上游任务或退款。
- 状态和 GLB 下载使用每任务独立凭证；不向浏览器返回服务商密钥或 CDN 签名地址。后端下载仅接受 HTTPS 白名单主机，不跟随跳转、不向 CDN 转发服务商鉴权头；GLB 在服务端和浏览器两次校验。
- 历史保存三视图图片、提示词、尺寸和三视图模式标记；旧历史仍按普通单图恢复。裁切调整和 GLB 仅保留在当前结果会话，离开前请下载需要的模型。恢复历史后需重新确认裁切。

三视图生成、深度推断和模型重建均为 AI 推断，不代表精确三维测量或唯一正确的背面。生成质量仍需用真实样例人工检查。素材及三维衍生的使用需遵守仓库中的素材来源与许可证约定。

## 建模失败诊断

后端启用后不等于服务商鉴权、服务开通或额度正常；健康检查只代表本地服务可响应。页面的服务商任务编号出现前，尚未确认上游创建成功；HTTP 202 只是本地后端接收了任务。

失败时，页面和后端结构化日志现在保留供应商、失败阶段（上传／提交／查询／下载）、上游 HTTP 状态，以及符合白名单的公共错误码和 UUID RequestId。日志前缀为 `[model-jobs]`。不会输出原始上游错误消息、Key、鉴权头、图片 base64 或带签名的模型地址；未知错误码和不合规 RequestId 会省略。带未知后缀的混元错误码若属于已知公共类别，仅保留固定类别名（例如 `ResourceUnavailable.NotExist` 只显示 `ResourceUnavailable`），不反射后缀。HTTP 400 可能承载服务、鉴权或资源错误，不单独证明参数错误；已识别公共错误码优先于 HTTP 400 的泛化分类。

诊断解析会检查平铺或 Response 包装中的固定错误码字段，以及外层／嵌套的 RequestId。若响应头提供 X-TC-RequestId 或 X-Request-Id，也只保留通过 UUID 白名单且不等于后端凭证的值；非 JSON 响应同样可以保留这种安全编号。无效的早期候选不会遮挡后续安全字段。此为兼容性防护，不代表已确认当前上游响应使用了这些备用字段；仅有 HTTP 400 时仍不能判定具体原因，也不能追溯旧失败响应。不会根据原始 Message、error.type 或 error.param 猜测根因。

账户侧先只读检查服务开通状态、可用资源包与任务记录。中国大陆服务已开通不代表跨境流量也已开通；若后端实际出口位于海外，需核对官方访问区域限制。浏览器能登录控制台不证明后端请求出口合规，资源包已使用为 0 也不能单独证明上游没有创建任务或未产生费用。不要为诊断擅自开通后付费／跨境服务或重提建模。

| 页面错误                            | 建议检查                                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `provider_auth_failed`              | 后端当前供应商的 API Key 是否正确、有效、未被禁用；不要把服务商 Key 填进页面的后端访问令牌           |
| `provider_access_denied`            | 服务是否开通、账号权限、IP 白名单或官方接口是否变更                                                  |
| `provider_resource_limited`         | 可用积分／额度、资源占用或并发任务；ResourceInsufficient 的官方含义是资源不足，不单独断言为余额不足  |
| `provider_invalid_request`          | 模型版本、三视图字段与图片限制；混元兼容文档没有多视图 JSON 示例，仍需真实接口验证，不自动降级到单图 |
| `provider_rejected`                 | 仅有 HTTP 400，具体原因未确认；先检查服务开通状态和任务记录，不凭状态码盲目修改三视图或充值          |
| `provider_unavailable`              | 服务商资源不可用或暂时故障；检查服务是否开通及任务记录，不自动重提付费任务                           |
| `submission_uncertain`／`timed_out` | 先去当前服务商控制台检查任务记录，避免重复付费                                                       |

上游只读查询遇到暂时故障或限频可以重试；已返回 FAIL 的任务直接终止。付费提交始终不自动重试，HTTP 429／5xx 即使携带可识别错误码也按提交不确定处理。相同幂等标识保留原失败终态，不重新收费。

诊断改动需重启后端才会生效；重启会丢失内存中的旧任务、模型及幂等记录，先核对控制台任务记录。此前已失败且未保存上游详情的旧任务无法通过这次改动追溯原因。再次确认裁切并点击生成属于新付费请求，不是诊断操作。

## 维护与验证

- `src/three-view.ts`：无浏览器副作用的模式、比例、提示词与裁切校验。
- `src/three-view-crop.ts`、`src/three-view-editor.tsx`：裁切导出、预览和输入。
- `src/model-generation.ts`：独立建模客户端、会话配置、幂等提交与轮询。
- `src/three-view-result.tsx`：结果工作流；更换图片时销毁旧任务及对象 URL。
- `src/model-viewport.tsx`：按需加载 `model-viewer`，不在普通单图预览中初始化 3D 渲染。
- `server/model-jobs.mjs`：独立后端鉴权、校验、队列和 Tripo／混元兼容接口适配。
- `shared/model-contract.mjs`：前后端共用的 GLB 文件校验。

```sh
npm test
npm run build
```
